# PR：安全修复 · 后台分区管理 GET 匿名可读任职名单

分支 `feat/security-board-members-auth` → `main`。改动量：2 个文件，+141 / -2。

---

## 一句话

**匿名用户可通过 HTTP 请求读取任意讨论区分区的完整任职名单**，包括管理员与协管的 `userId`、昵称、头像、角色，以及**是谁任命的**（`grantedBy`）。

---

## 漏洞详情

| 项 | 内容 |
|---|---|
| **接口** | `GET /api/admin/forum/boards/{boardId}` |
| **问题代码** | 路由文件 GET 分支，无任何鉴权 |
| **引入提交** | `4c57918` fix(forum): 分区管理与草稿边界（2026-11-05） |
| **严重度** | **P1** |

### 泄露的内容

```json
{
  "boardId": "...",
  "myRole": "member",
  "members": [{
    "userId": "...",        // 用户 id
    "nickname": "...",      // 昵称
    "avatarUrl": "...",     // 头像
    "role": "owner",        // 区长 / 协管
    "grantedBy": "...",     // 谁任命的 ← 最敏感
    "createdAt": 1234567890
  }]
}
```

**最敏感的是 `grantedBy`**——它暴露了站内的任命关系链。

---

## 根因：两层都没兜住

这个文件头注释写得很清楚：

> 权限不在这一层再判一遍：各方法自己调 assertBoardManager / assertCanAdmin，路由只做「把 body 拆成参数」。两处各判一套正是权限判定漂移的来源。

**这个理念本身是对的**——避免路由层与服务层各判一套。

问题是：POST 的六个管理动作确实都在 service 层做了校验，**但 GET 走的 `listMembers` 与 `boardRoleOf` 被写成了纯查询**——`listMembers` 的参数名是 `_ctx`，下划线就是「有意不用」的证据。

| 层 | 应有防护 | 实际 |
|---|---|---|
| 路由层 | `assertCanAdmin(ctx)` | ❌ 没有（文件里连 import 都没有） |
| 服务层 | `listMembers` 内部校验 | ❌ 没有 |

### 一个刺眼的对比

全站 **30 个 admin 路由，29 个都调了 `assertCanAdmin`，唯独这个没有**。

> 这个漏洞是安全审计时靠「同目录其它 29 个都 import 了 assertCanAdmin，唯独这个没有」发现的。
> **同类对比是发现异常的有效方法。**

---

## 修复：方案 C —— 本区管理者与站方管理员都能看

使用者 2026-11-16 裁定选方案 C，理由：**「看名单」是读，不是管**。区长与协管本就该能看自己区的任职情况。

所以**不能**直接上 `assertCanAdmin`——那会把区长挡在外面。

```ts
assertCanWrite(ctx);                        // 挡匿名
const role = await service.boardRoleOf(boardId, ctx.userId);
if (!isAdmin(ctx) && role === null) {
  throw err.forbidden('只有本区管理者与站方管理员可以查看任职名单。');
}
```

| 请求者 | 修复前 | 修复后 |
|---|---|---|
| 匿名 | **200 + 完整名单** | 401 `unauthenticated` |
| 登录但无关 | **200 + 完整名单** | 403 `forbidden` |
| 本区区长 | 200 | 200 |
| 本区协管 | 200 | 200 |
| 站方管理员 | 200 | 200 |

**POST 分支未动**，权限仍在服务层各方法里判断，符合原设计的「权限下沉」约定。

## 一个结构性问题（本 PR 不修，但值得提）

审计还发现：**`src/` 下没有 `middleware.ts`**，admin 路由的鉴权完全依赖每个 `route.ts` 自己调用。任何新增 admin 路由若忘记调 `assertCanAdmin`，**不会有任何兜底拦截**。

**本次漏洞正是这个结构缺口的产物。**

建议（非本 PR 范围）：写一个测试遍历 `src/app/api/admin/**/route.ts`，断言每个文件都 import 了 `assertCanAdmin`。
用测试守住约定，不改运行时、零风险。
