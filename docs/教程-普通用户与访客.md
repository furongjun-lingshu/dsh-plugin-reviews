# 使用教程 · 普通用户与访客

> 这份教程面向**访客**和**普通用户**。
> 文中 🔓 表示不登录也能用，🔐 表示需要先登录。
> 想知道怎么投稿（写评测、提交插件、建整合包），直接跳到[第 10 节](#10-我想投稿)。

---

## 1. 这是什么站

这是一个 **DSH 插件测评站**。它不是插件下载站，也不做商店——它做的事是：**有人真的把一个插件跑起来，然后告诉你好不好用，以及凭什么这么说。**

站上有三类内容：

| 内容 | 是什么 | 举例 |
|---|---|---|
| **插件** | 站点收录的 DSH 插件，每个插件站点会记录它的仓库、版本、简介 | 一个做代码格式化的插件 |
| **评测** | 有人对这个插件做完整测试后的报告 | 「这个插件在 X 场景真有用，附复现步骤」 |
| **整合包** | 若干插件打包在一起的组合，有安装命令 | 「新手入门包：装了这 6 个就够用」 |

三类之间是这样一个关系：**插件是被测的对象，评测是关于它的结论，整合包是打包好的推荐组合。**

除了这三类，站上还有：

- **讨论区**：用户可以互相提问、交流（不是向站方报告问题，见第 11 节）
- **精选专栏**：站方编辑挑选的推荐位

## 2. 不登录能做什么 🔓

**不注册也能用站上大部分内容。** 具体是：

| 能做的事 | 在哪 |
|---|---|
| 浏览插件目录、看插件详情 | 「插件」 |
| 读评测全文（含结论与证据链） | 「评测」或插件详情页 |
| 看整合包与其安装命令 | 「整合包」 |
| 看精选专栏 | 「精选」 |
| 看讨论区的帖子和回复 | 「讨论区」 |
| 读规范页 | 「规范」 |

**不能做的**：所有「产生内容」和「记录你的偏好」的操作——发评测、评论、点赞、收藏、发帖、举报，都需要登录。

## 3. 登录，以及它带来什么

### 3.1 怎么登录

页面**右上角**有登录入口。本站用 **GitHub 账号**识别你的身份——点登录后跳转到 GitHub 授权，不需要另外注册密码。

第一次登录会让你确认昵称。默认取你的 GitHub 显示名，没有显示名就用用户名，可以改。

### 3.2 登录前后的对照

| 功能 | 访客 🔓 | 登录后 🔐 |
|---|---|---|
| 看插件 / 评测 / 整合包 | ✅ | ✅ |
| 看讨论区 | ✅ | ✅ |
| 发表评测 | ❌ | ✅ |
| 评论、回复 | ❌ | ✅ |
| 点赞（有帮助 / 赞） | ❌ | ✅ |
| 收藏插件 / 整合包 / 帖子 | ❌ | ✅ |
| 在讨论区发帖 | ❌ | ✅ |
| 举报违规内容 | ❌ | ✅ |
| 提交插件 / 创建整合包 | ❌ | ✅ |
| 收到通知（回复、审核结果） | ❌ | ✅ |

### 3.3 要登录才看得到的功能在哪

登录后，右上角会从「登录」变成你的账户菜单，里面有：

- 通知（有人回复你、你提交的内容有审核结果）
- 我的（个人中心：评测、整合包、收藏、讨论区帖子、设置）

## 4. 找插件

顶部导航「插件」是插件目录。

### 4.1 目录能做什么

| 操作 | 说明 |
|---|---|
| 搜索 | 可以按插件名、仓库名或简介搜。搜索是**站内搜索**，不会去 GitHub 现查，仅能查到站点已经收录的插件 |
| 按分类筛选 | 侧栏的分类标签，点一下只显示该类 |
| 排序 | 可以按「更新时间」或「评测数量」排 |
| 翻页 | 底部页码 |

> 如果筛完发现一条都没有，页面会告诉你是「目录本身就没有」还是「筛选条件太窄」——后者会给一个清除条件的按钮。

### 4.2 插件详情页怎么看

点进任意插件，页面会给出这些信息：

| 区块 | 内容 |
|---|---|
| 基本信息 | 插件名、所属仓库、路径、简介 |
| 测评等级 | 这个插件被测评到什么程度：**未测评 / 已快测 / 已标测** |
| 安全审计 | 是否做过安全审计（也可能显示「未标注」，表示数据不足） |
| 评测列表 | 别人对它的评测，**官方测评排在最前** |
| 收藏 / 反馈入口 | 收藏这个插件；发现资料写错了可以反馈 |

**「测评等级」是什么意思**：

- **未测评**：还没有人做过完整测试
- **已快测**：做过快速测试，结论覆盖范围较窄
- **已标测**：做过标准测试，覆盖主要使用场景

详细内容可以前往「规范」查看

看到「未测评」不代表插件不好——只是还没人测过。

## 5. 读评测：本站最关键的一点

### 5.1 这里没有星级，也没有总分

大多数测评站会给「4.5 星」或「85 分」。**本站不给。**

一篇评测的结论只能是下面五个之一：

| 结论 | 含义 | 需要证据链 |
|---|---|---|
| **真有用** | 实测证明它能解决它声称要解决的问题 | ✅ 必须 |
| **帮倒忙** | 用了反而更糟，或者有副作用 | ✅ 必须 |
| **没啥差别** | 用了和不用区别不大 | ✅ 必须 |
| **还说不准** | 数据不足以判断 | 不需要 |
| **没法测** | 客观上无法测试 | 不需要 |

**为什么这样设计**：一个分数会把「在什么场景下有用」这个最重要的信息抹平。五状态 + 场景描述，读者才能自己判断「这符合我的情况吗」。

### 5.2 什么是证据链（就是能点开的记录）

凡是给出「真有用 / 帮倒忙 / 没啥差别」的评测，**必须附带至少一条可点开的链接**作为证据：

- 复现步骤或日志
- A/B 对比记录
- 测试读数截图

这是强制要求，写评测时不符合要求就提交不上去。所以你在站上看到的有结论的评测，背后都有东西可查。

> 不是感受，是能复核的东西。没有证据链的评测，结论不能是这三者之一。

### 5.3 评测列表上的其他标记

| 标记 | 含义 |
|---|---|
| **站点评测** | 官方测评。由站方专职测评员产出，可信度更高 |
| **社区评测** | 普通用户写的评测 |
| 有帮助 | 这篇评测对你是否有帮助 |

同一个插件可以有多篇评测。官方测评**置顶显示**，社区评测排在后面，但都会列出来，不会互相覆盖。

## 6. 整合包：和插件有什么不同

导航「整合包」里是**别人打包好的插件组合**。区别在于：

| | 插件 | 整合包 |
|---|---|---|
| 是什么 | 单个功能单元 | 一组插件的合集 |
| 怎么用 | 自己装 | 有一条安装命令，复制即用 |
| 谁维护 | 插件作者 | 整合包作者 |

### 6.1 整合包详情页

| 区块 | 说明 |
|---|---|
| 版本列表 | 每个版本记录了它包含哪些插件、在什么时间发布 |
| 安装命令 | **可一键复制**，粘到终端就能装 |
| 公开状态 | 只有「已发布」的版本对外可见；起草中或审核中的版本不公开 |
| 有帮助 / 举报 | 觉得好用点个有帮助；有问题可以举报 |

### 6.2 一个常见的困惑

**整合包收藏和插件收藏是分开的。** 收藏了一个整合包，在「收藏 → 插件」里找不到它；
反过来也一样。站上有三类独立的收藏夹：插件、整合包、帖子（见第 9 节）。

## 7. 精选专栏

导航「精选」是**站方编辑挑选的推荐位**。它和普通评测的区别：

- 精选是**栏目**，按期发布，一期里面有若干推荐
- 精选是**推荐位，不是结论**：挑选时优先选已有站方测评的插件，但精选本身不构成对插件的评测——某个插件好不好用，以它详情页的测评列表为准
- 想知道某篇评测是不是站方测评，看它有没有「站点评测」标记

## 8. 讨论区

「讨论区」是用户之间交流的地方。

> **注意区分**：讨论区是「用户之间讨论」，不是「向站方报告问题」。
> 发现内容违规、资料写错、站点有 bug，请走第 11 节的三条通道，不要发帖。

### 8.1 分区与帖子

讨论区按**分区**组织。打开讨论区先看到分区列表，点进某个分区才看到里面的帖子。

每个分区有自己的发帖规则（比如「官方公告区」只有站方能发，「综合讨论区」所有登录用户都能发）。
进入分区页会看到当前分区的帖子列表，可以按「最新发布」或「最后回复」排序，置顶帖始终在最前。

### 8.2 发帖 🔐

在分区页点「发帖」，填写：

- **标题**（最多 120 字）
- **正文**（支持 Markdown，最多 2 万字）
- **图片**（可选，最多 9 张）

发出去之后会发生什么：

- 内容正常 → 直接显示在列表里
- 命中自动审核规则 → 变成**审核中**，只有你自己和站方看得到，其他人看不到

**草稿**：没写完可以存草稿，在「我的 → 讨论区帖子」里找回来继续写。草稿最多 100 篇。

**已发的帖子还能改吗**：能。作者可以编辑标题和正文。
注意**编辑后会重新过一遍自动审核**——先发干净内容再改成违规内容的做法行不通。

### 8.3 两层回复 🔐

回复只有**两层**：

```
帖子
 └─ 回复（第一层）
     └─ 对回复的回复（第二层，到此为止）
```

第二层不能继续往下回复。这样设计是为了避免楼层无限嵌套之后没人读得懂。

几个细节：

- 第一层回复可以带图片，第二层**不能带图**
- 每一层都可以点赞（点的是这条回复本身）
- 作者删除帖子是**软删**：内容不显示了，但收藏过它的人仍能看到「该帖已被删除」的痕迹

### 8.4 举报 🔐

帖子和回复上都有举报按钮。举报后管理员会处理，结果会通过**站内通知**告诉你。

同一项内容举报过一次就不要再重复举报——系统会告诉你正在处理中。

## 9. 收藏与个人中心

### 9.1 三类收藏，互相独立

点心形 / 星形按钮收藏时，站上会自动按内容类型分开放：

| 类型 | 在「我的收藏」的哪一页 |
|---|---|
| 插件 | 插件 |
| 整合包 | 整合包 |
| 帖子 | 帖子 |

**它们不互通**：插件收藏夹里不会出现整合包，整合包收藏夹也不会出现插件。

### 9.2 收藏夹

每类内容有自己的收藏夹体系：

- 每类都有且只有一个**默认夹**（不可删除）
- 可以自建更多收藏夹，同一类内不能重名，**不同类型可以重名**（插件夹「常用」和帖子夹「常用」是两个夹）
- 一个收藏夹只能装**同一种类型**的内容

**删除收藏夹时会怎样**（容易误解）：夹内收藏**不会被删掉**，而是**移回默认夹**。
删除收藏夹等于「把东西倒回默认夹，然后扔掉这个盒子」。

### 9.3 个人中心

点右上角账户菜单 →「我的」，左侧有这些栏目：

| 栏目 | 内容 |
|---|---|
| 评测 | 你的草稿、提交记录、已发布 |
| 整合包 | 你创建的整合包 |
| 收藏 | 三类收藏夹 |
| 我的插件 | 认领到你名下、或正在审核中的插件 |
| 通知 | 有人回复你、你的投稿有审核结果 |
| 讨论区帖子 | 你在讨论区发的帖子与草稿 |
| 个人设置 | 昵称、GitHub 绑定、账户信息 |

## 10. 我想投稿

站上有四条投稿路径，按你想做的事情选：

| 你想做 | 从哪进 | 需要什么 |
|---|---|---|
| 写一篇评测 | 插件详情页的「写一篇评测」 | 登录；能说清测了什么、结论是什么 |
| 让站上收录一个插件 | 插件页的「提交插件」 | 登录；插件所在的 GitHub 仓库地址 |
| 做一个整合包 | 「我的 → 整合包」的「新建整合包」 | 登录；选好要包含的插件 |
| 在讨论区发帖 | 讨论区 → 分区 → 发帖 | 登录；该分区允许你发帖 |

### 10.1 写评测 🔐

从**插件详情页**的「写一篇评测」进来（评测列表页没有这个入口——必须先选定被测的插件）。
这是本站最核心的投稿。一篇评测要写清楚：

| 内容 | 要求 |
|---|---|
| 标题 | 一句话说明你测了什么 |
| 被测插件与版本 | 必须指定 |
| 正文 | Markdown；写清测试场景、步骤、结果 |
| **结论** | 五选一：真有用 / 帮倒忙 / 没啥差别 / 还说不准 / 没法测 |
| **证据链** | 结论是前三者之一时**必填**，至少一条能点开的链接 |
| 测评等级 | 快测 / 标准 / 深度 / 安全审计，按你实际测到什么程度选 |

**常见卡点**：想给「真有用」但填不出证据链 → 提交会被拒。
这时候要么补上复现步骤，要么把结论改成「还说不准」。这不是刁难，是为了让结论可复核。

写好之后：

1. 先存草稿（随时可继续）
2. 提交 → 进入审核
3. 审核通过 → 公开；不通过 → 在「我的 → 评测 → 提交记录」里看原因并修改重提

### 10.2 提交插件 🔐

给一个还没被收录的插件：填 GitHub 仓库地址（如果插件在仓库子目录里，还要填子路径），提交后等站方审核收录。

### 10.3 创建整合包 🔐

入口在「我的 → 整合包」页的「新建整合包」，从你已有的收藏夹里挑插件组成一个包。
选好要包含的插件 → 写名称与说明 → 提交审核 → 通过后发布。
整合包是**按版本**管理的：每次改动都生成一个新版本，旧版本不会被覆盖。

### 10.4 在讨论区发帖 🔐

见第 8.2 节。

### 10.5 关于「成为测评员 / 开发者」

站上有**测评员**和**开发者**两种附加身份，需要自己申请、站方审核。
入口在「个人设置」页的身份一栏旁边。

> 本教程不展开申请流程——那部分内容还在整理中。只知道入口在哪就够开始时用了。

## 11. 遇到问题该找谁（本站最容易用错的地方）

站上有**三条**看起来都能「提问题」的通道，但它们管的事完全不同。
**用错通道的后果是等了很久没人理。**

| | 举报 | 反馈资料错误 | 问题反馈 |
|---|---|---|---|
| **入口在哪** | 评测 / 评论 / 帖子 / 回复 / 整合包版本上的「举报」按钮 | 插件详情页 | 右上角账户菜单 →「反馈问题」，需登录 |
| **管什么** | 内容违规 | 插件资料写错 | 站点本身的问题 |
| **具体包括** | 垃圾广告、辱骂、错误信息、版权抄袭 | 只有两项：**展示名**、**简介** | 功能异常、账号问题、使用建议 |
| **不管什么** | 资料写错 | 分类错误、评测内容 | 某篇内容的对错 |
| **结果怎么看** | 站内通知 | 由管理员处理 | 可在「问题反馈」页看处理进度 |

### 三句话记住怎么选

1. **「这篇内容是假的 / 骂人的 / 抄的」** → 举报
2. **「这个插件的名字或简介写错了」** → 反馈资料错误
3. **「网站点了没反应 / 我账号登不上 / 建议加个功能」** → 问题反馈

> ⚠️ 讨论区**不是**反馈通道。在讨论区发帖说「你们这个 bug 怎么还没修」大概率没人处理——
> 讨论区是用户之间交流的地方，站方不一定看得到。请走上面的三条。

## 12. 常见问题

**Q：不注册能看评测吗？**
能。站上所有评测、插件、整合包、讨论区内容都不登录也能看。需要登录的是「产生内容」和「记录偏好」的操作，见第 3.2 节的对照表。

**Q：为什么非要 GitHub 账号？**
本站用 GitHub 账号识别身份，不需要另外注册密码。你只要有一个 GitHub 账号就能登录。

**Q：为什么这里的评测没有星级？**
因为星级会把「在什么场景下有用」这个最重要的信息抹平。本站的结论只有五个状态，其中三个必须附证据链（见第 5 节）。

**Q：为什么我写的评测提交不上去？**
最常见的原因是**选了「真有用 / 帮倒忙 / 没啥差别」但没填证据链**。这三个结论必须至少有一条能点开的链接。
补上复现步骤，或把结论改成「还说不准」，就能提交。

**Q：帖子发出去了但别人看不到？**
可能进入了**审核中**状态。命中自动审核规则的帖子只有你自己和站方能看到，审核通过后才公开。

**Q：收藏了一个插件，在「收藏 → 整合包」里找不到？**
三类收藏是**互相独立**的。插件收藏在「收藏 → 插件」里，整合包在「收藏 → 整合包」里，帖子在「收藏 → 帖子」里。

**Q：删了收藏夹，里面的收藏丢了吗？**
没丢。删除收藏夹时，夹内收藏会**移回默认收藏夹**（见第 9.2 节）。

**Q：我之前收藏的东西后来下架了，还能取消收藏吗？**
能。目标下架不影响你取消收藏。

**Q：同一个插件可以有好几篇评测吗？**
可以。而且同一插件只能有一篇官方测评；官方测评置顶显示，社区测评排在后面，都会列出来。

**Q：怎么知道自己是不是被回复了？**
登录后右上角账户菜单里有「通知」，有人回复你、你的投稿有审核结果都会出现在那里。

**Q：讨论区能问「这个 bug 什么时候修」吗？**
不建议。讨论区是用户之间交流的地方，站方不一定看得到。站点问题请走「问题反馈」（见第 11 节）。

**Q：我能在讨论区自己开一个新分区吗？**
可以申请，需要站方审核。具体流程不在本教程范围内。

**Q：评测里说的「快测 / 标测 / 深度」是什么意思？**
是**测评等级**，表示测评覆盖到什么程度：快测覆盖窄、标测覆盖主要场景、深度测更全面。
插件详情页会显示这个插件当前被测到什么档次（见第 4.2 节）。
