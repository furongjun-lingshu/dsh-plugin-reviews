# 部署与自动发布

> 线上：`https://review.lingshulab.com`（服务器 `5.231.26.36`，Debian 13，Docker 四角色）。
> 这份文档只写**当前真实做法**；容器细节见 [`docker约定.md`](./docker约定.md)，备份见 [`备份与恢复.md`](./备份与恢复.md)。

## 1. 服务器布局

```
/root/dsh-plugin-review/
├─ repo/                    源码（不是 git clone，由发布包解出来）
│  └─ docker/
│     ├─ compose.yaml       migrate / web / worker / nginx
│     └─ .env               部署参数（不在 git 里，必须保留）
├─ data/                    SQLite + 媒体（容器内 UID 10001）
├─ backups/                 数据库热备（含 pre-deploy-*）
├─ certs/                   TLS 证书（只读挂进 nginx）
└─ repo.old-<时间戳>/        上一版源码快照（自动保留最近 2 份，用于回滚）
```

Docker 自身数据在 `/root/docker`（`daemon.json` 的 `data-root`）。

## 2. 自动发布（GitHub Actions）

工作流：[`.github/workflows/deploy-production.yml`](../.github/workflows/deploy-production.yml)

- **触发**：push 到 `main`（即 PR 合并后）；也可以在 Actions 页面手动 `Run workflow`；
- **内容**：`git archive HEAD` 打包（只含受版本控制的文件，`.env`/数据/备份永不进包）→ `scp` 到 `/tmp` → SSH 执行 [`deploy/deploy-remote.sh`](../deploy/deploy-remote.sh)：
  1. 部署前数据库热备（`pre-deploy-<短 sha>`）；
  2. 解包到 `repo.new`，把 `docker/.env` 带过去；
  3. 原子切换 `repo` ↔ `repo.old-<时间戳>`；
  4. `docker compose up -d --build`（migrate → web/worker → nginx）；
  5. 等 `web` healthy，再验 `/api/health` 与首页 200；
  6. 失败自动切回上一版源码并重建。

### 一次性配置（仓库管理员）

SSH 登录方式为**专用部署密钥**（不是密码）：

1. 生成一对 ed25519 密钥（本机已生成，私钥不要在仓库里提交）；
2. 把公钥追加到服务器 `/root/.ssh/authorized_keys`；
3. 在 GitHub 仓库 **Settings → Secrets and variables → Actions → New repository secret** 新增：
   - 名称：`DEPLOY_SSH_KEY`
   - 值：**私钥全文**（`-----BEGIN OPENSSH PRIVATE KEY-----` 到结束，含换行）。

主机公钥固定写在 [`deploy/known_hosts`](../deploy/known_hosts)，工作流用 `StrictHostKeyChecking=yes`，不做 `ssh-keyscan`。

### 手动发布（Actions 不可用时）

```bash
# 本机
git archive --format=tar.gz -o /tmp/dsh-deploy-$(git rev-parse --short HEAD).tar.gz HEAD
scp -i <部署私钥> /tmp/dsh-deploy-*.tar.gz root@5.231.26.36:/tmp/

# 服务器
bash -s -- /tmp/dsh-deploy-<sha>.tar.gz <sha> < deploy/deploy-remote.sh
```

## 3. 回滚

- 代码：部署失败会自动回滚；也可以手动把 `/root/dsh-plugin-review/repo.old-<时间戳>` 换回 `repo` 后
  `cd /root/dsh-plugin-review/repo/docker && docker compose up -d --build`。
- 数据：用 `backups/` 里对应 `pre-deploy-*` 的恢复点，按 [`备份与恢复.md`](./备份与恢复.md) 操作。

## 4. 发布后自检

```bash
curl -fsS https://review.lingshulab.com/api/health
cd /root/dsh-plugin-review/repo/docker && docker compose ps
docker compose logs --tail=50 migrate web worker
```

> ⚠️ 服务器上的 `docker/.env` 是唯一一份生产配置：切换源码目录时必须保留（脚本已处理）。
> 不要在服务器上 `git clone` 覆盖 `repo/`，也不要提交任何 `.env`。
